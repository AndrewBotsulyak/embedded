## GPIO и прерывания

- **GPIO** — настройка в ESP-IDF через `gpio_config()` (маска пинов, режим, подтяжка, тип прерывания), чтение — `gpio_get_level()`.
- **Подтяжка (pull-up/pull-down)** — задаёт уровень на пине, когда он ни к чему не подключён. Без неё вход «висит в воздухе» и ловит наводки.
- **ISR (обработчик прерывания)** — вызывается по фронту сигнала. Должен быть максимально коротким: только выставить флаг, вся логика — в основном цикле.
- **`IRAM_ATTR`** — размещает ISR в RAM, чтобы обработчик работал даже когда flash недоступен.
- **`gpio_install_isr_service()` + `gpio_isr_handler_add()`** — общий сервис прерываний и обработчик на конкретный пин, с передачей пользовательских данных (`void* arg`).
- **Дребезг контактов (debounce)** — механические контакты дают пачку фронтов при одном нажатии. Фильтруется по времени: событие принимается, только если уровень стабилен дольше `DEBOUNCE_DELAY` (~20 мс).

## Организация кода

- **Superloop** — бесконечный `loop()`, в котором последовательно опрашиваются все подсистемы. Никаких блокирующих `delay()`, иначе рассыпается вся тайминговая логика.
- **Неблокирующая задержка** — вместо `delay()` сравниваем `millis()`/`esp_timer_get_time()` с меткой прошлого события.
- **Конечный автомат (FSM)** — состояния + длительности + переходы. Основа светофора: переключение по таймеру, без задержек в коде.
- **`vTaskDelay(pdMS_TO_TICKS(ms))`** — FreeRTOS-задержка, отдающая процессор другим задачам. Задача обязана периодически «отпускать» CPU, иначе сработает task watchdog.

## Время и таймеры

- **`millis()` / `micros()`** — время с момента старта. `millis()` даёт разрешение 1 мс — для быстрых событий (реле ~11 мс) слишком грубо, нужен `micros()`.
- **`esp_timer`** — программный таймер ESP-IDF на микросекундах: `esp_timer_start_periodic()` (повторяющийся) и one-shot (перезапускается вручную). Колбэк выполняется в контексте задачи таймера — блокировать его нельзя.
- **GPTimer** — аппаратный таймер общего назначения. `resolution_hz` задаёт цену тика (1 МГц = 1 мкс), `alarm_count` — порог срабатывания, `auto_reload_on_alarm` — автосброс счётчика. Даёт точный период независимо от загрузки CPU.

## ADC (аналого-цифровое преобразование)

- **Разрядность** — 12 бит → RAW = 0…4095.
- **Аттенюация** — ослабление входного сигнала для расширения диапазона. `ADC_ATTEN_DB_12` ≈ 0…3.1 В.
- **Oneshot-режим** — `adc_oneshot_new_unit()` + `adc_oneshot_config_channel()`, чтение по требованию через `adc_oneshot_read()`.
- **Делитель напряжения** — потенциометр/фоторезистор в паре с резистором: средняя точка даёт напряжение, пропорциональное сопротивлению.
- **Ручной расчёт** `U = RAW / 4095 * VREF` — предполагает идеальную линейность и точный VREF. На практике даёт систематическую ошибку (в замерах ~4.7 %).
- **Калибровка (Curve Fitting)** — `adc_cali_create_scheme_curve_fitting()` + `adc_cali_raw_to_voltage()`. Использует заводские коэффициенты из **eFuse**, индивидуальные для каждого чипа — константу с одной платы нельзя переносить на другую.
- **Вывод**: ручной пересчёт годится для относительных величин (положение ручки, пороги), калиброванный — для реальных вольт.

## PWM (ШИМ)

- **Скважность (duty)** — доля периода, когда сигнал в HIGH. Определяет средний ток/яркость/обороты.
- **Программный PWM** — `digitalWrite()` + `millis()`/`delay()` вручную. Прост, но скважность «плывёт» от любой задержки в цикле.
- **Аппаратный PWM (LEDC)** — `ledc_timer_config()` (частота + разрешение) → `ledc_channel_config()` (пин + канал) → `ledc_set_duty()` + `ledc_update_duty()`. Периферия формирует сигнал сама, CPU не участвует.
- **Разрешение PWM** — 13 бит → duty 0…8191. Масштабирование ADC → duty: `raw * maxPWM / maxADC`.
- **Hardware fade** — плавное изменение скважности силами периферии: `ledc_fade_func_install()` **после** конфигурации канала, `ledc_set_fade_with_time()` настраивает, `ledc_fade_start()` запускает. Из колбэка таймера обязателен флаг `LEDC_FADE_NO_WAIT`.
- **Гистерезис** — разные пороги на включение и выключение, чтобы выход не «дребезжал» на границе (LDR: зажигаем на 65 %, гасим ниже 60 %).

## Силовая часть: реле, транзисторы, моторы

- **Реле** — электромеханический ключ. Модуль SRD-05VDC часто **инверсный (active low)**: `LOW` на `IN` = замкнуто. Контакты: `COM` (общий), `NC` (нормально замкнут), `NO` (нормально разомкнут).
- **Время срабатывания реле** — измеренное ≈ 10.9 мс. Растёт при пониженном питании катушки (3.3 В вместо 5 В) и по мере нагрева катушки.
- **Биполярный транзистор (2N2222, NPN)** — управляется **током базы** через резистор (470 Ом → ≈5.5 мА). Ограничен по току коллектора (~600–800 мА).
- **MOSFET (IRLZ44N)** — управляется **напряжением на затворе**. *Logic-level*: порог 1–2 В, полностью открывается от 3.3 В без драйвера. Обычный IRF44N на 3.3 В остался бы полуоткрытым и грелся.
- **Low-side switch** — нагрузка сверху, транзистор между нагрузкой и землёй.
- **Общая земля** — земли ESP32 и внешнего источника обязательно соединены, иначе у базы/затвора нет опорного потенциала.
- **Flyback-диод** — параллельно мотору, катодом к «+». Гасит выброс обратной ЭДС при закрытии ключа, без него транзистор пробивает.
- **Резистор затвора** (100–220 Ом) ограничивает бросок тока при перезарядке ёмкости затвора; подтяжка затвора к GND (10 кОм) держит ключ закрытым во время загрузки платы.

## Инструменты

- **PlatformIO + Arduino framework** — ранние проекты (`platformio.ini`, `setup()`/`loop()`).
- **ESP-IDF** — нативный фреймворк: `app_main()`, CMake-компоненты, `idf.py set-target esp32s3` / `build` / `flash monitor`.
- **`ESP_ERROR_CHECK()`** — обёртка, роняющая программу с понятным логом при ошибке драйвера.
- **`ESP_LOGI/E`** — логирование с тегом и уровнем вместо `printf`.
- **devcontainer** — образ с ESP-IDF и QEMU: сборка и запуск без железа.
