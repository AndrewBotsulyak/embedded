# Светофор с моторчиком

Домашнее задание, модуль 2. Светофор на ESP32-S3 с полным циклом состояний, к которому добавлен мотор: он плавно разгоняется на зелёный сигнал и плавно тормозит на жёлтый. Мотор коммутируется MOSFET-транзистором **IRLZ44N** и питается от **отдельного источника 5 В**.

## Оборудование

| Компонент | Назначение |
|---|---|
| ESP32-S3 | контроллер |
| 3 светодиода (красный / жёлтый / зелёный) + токоограничивающие резисторы | сигналы светофора |
| MOSFET IRLZ44N | ключ нижнего плеча для мотора |
| DC-моторчик | исполнительный механизм |
| Источник питания 5 В | питание мотора, отдельно от платы |
| Диод (1N4007 / SR340) | защита от обратной ЭДС мотора |

IRLZ44N выбран потому, что это **logic-level** MOSFET: порог открытия ~1–2 В, поэтому он полностью открывается от 3.3 В с ножки ESP32 напрямую, без драйвера затвора. Обычный IRF44N на 3.3 В остался бы полуоткрытым и грелся.

## Подключение

| Сигнал | GPIO |
|---|---|
| Красный светодиод | `GPIO14` |
| Жёлтый светодиод | `GPIO13` |
| Зелёный светодиод | `GPIO12` |
| ШИМ на затвор MOSFET | `GPIO4` |

Мотор подключён по схеме low-side switch:

```
      +5 В (отдельный БП)
        │
        ├──────┐
      [мотор]  │
        │     ─┴─ диод (катод к +5 В)
        ├──────┘
        │
        D
GPIO4 ─[R]─ G  IRLZ44N
        S
        │
       GND ──── общая земля с ESP32 и с БП
```

Два момента, без которых схема не работает или выгорает:

- **Земля ESP32 и земля источника 5 В должны быть соединены.** Иначе у затвора нет опорного потенциала и транзистор не управляется.
- **Диод параллельно мотору обязателен**, катодом к плюсу. При закрытии транзистора индуктивность обмотки даёт выброс обратной ЭДС, который пробивает MOSFET.

Резистор в цепи затвора (100–220 Ом) ограничивает бросок тока при перезарядке ёмкости затвора; подтяжка затвора к земле (10 кОм) держит транзистор закрытым, пока пин ESP32 находится в высокоимпедансном состоянии при загрузке.

## Логика работы

Конечный автомат из пяти состояний, полный цикл — 16 секунд:

| Состояние | Длительность | Что происходит |
|---|---|---|
| `GREEN_STATE` | 5 с | горит зелёный, мотор разгоняется до максимума за 2 с |
| `GREEN_BLINK_STATE` | 2 с | зелёный мигает с периодом 500 мс |
| `YELLOW_STATE` | 2 с | горит жёлтый, мотор тормозит до нуля за 2 с |
| `RED_STATE` | 5 с | горит красный |
| `RED_YELLOW_STATE` | 2 с | горят красный и жёлтый |

Переключение состояний построено на `esp_timer`, без блокирующих задержек:

- `state_timer` — одноразовый таймер, перезапускается в конце каждого перехода на длительность нового состояния (`getCurrentTimeOutUs()` переводит секунды из `state_duration[]` в микросекунды);
- `blink_timer` — периодический таймер на 500 мс, запускается только на время `GREEN_BLINK_STATE` и останавливается на всех остальных.

## Управление мотором

Скорость задаётся аппаратным ШИМ через драйвер LEDC:

| Параметр | Значение |
|---|---|
| Частота | 5 кГц |
| Разрешение | 12 бит (duty 0…4095) |
| Таймер / канал | `LEDC_TIMER_0` / `LEDC_CHANNEL_0` |
| Режим | `LEDC_LOW_SPEED_MODE` |

Плавный разгон и торможение сделаны аппаратным fade — процессор не участвует в изменении скважности, всё считает периферия. Порядок вызовов здесь важен и неочевиден:

1. `ledc_timer_config()` → `ledc_channel_config()` → **только потом** `ledc_fade_func_install()`. Install ищет уже созданный канал, чтобы получить адрес регистра прерывания, и падает, если канала ещё нет.
2. `ledc_set_fade_with_time()` только **настраивает** fade; запускает его `ledc_fade_start()`. Флаг `LEDC_FADE_NO_WAIT` обязателен, потому что вызов происходит из callback-а `esp_timer` — с `WAIT_DONE` задача таймера заблокировалась бы на 2 секунды.
