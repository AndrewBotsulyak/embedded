# ДЗ 3.2 — Фильтрация сигнала АЦП (ESP32-S3)

## Задание

1. Подключить LDR (фоторезистор) к ESP32 в виде делителя напряжения, выход — на один из каналов ADC1.
2. Подключить светодиод к любому доступному GPIO.
3. Реализовать чтение значений с АЦП в режиме **oneshot**.
4. Реализовать **Simple Moving Average (SMA)** для фильтрации значений освещённости.
5. Используя отфильтрованные данные:
   - когда становится темно — светодиод включается;
   - когда становится светло — светодиод выключается.
6. Светодиод не должен мерцать при незначительных колебаниях освещённости.
7. Реализовать **два порога (гистерезис)** для предотвращения мерцания.

## Схема

| Узел | Пин | Роль |
|---|---|---|
| Питание делителя | `GPIO4` (`POWER_PIN`) | программно выставлен в `1`, играет роль «+» для делителя |
| Выход делителя (LDR) | `GPIO7` (`ADC_PIN`) | вход АЦП, на ESP32-S3 это `ADC1_CH6` |
| Светодиод | `GPIO13` (`LED_PIN`) | управляется ШИМ через LEDC |

Фоторезистор включён делителем напряжения: верхнее плечо запитано с `GPIO4`,
средняя точка идёт на `GPIO7`, нижнее плечо — фиксированный резистор на `GND`.

### Аппаратная фильтрация (RC-цепь)

Параллельно средней точке делителя установлена **RC-цепь с конденсатором 100 пФ**.
Она работает как пассивный ФНЧ первого порядка и подавляет высокочастотные наводки
до того, как сигнал попадёт на вход АЦП: помехи от ШИМ светодиода, наводки от питания
и коммутационный шум самого АЦП (входной цепи SAR нужен низкоимпедансный источник,
а делитель на LDR имеет довольно высокое выходное сопротивление).

Таким образом фильтрация двухступенчатая:

```
LDR-делитель ──► RC (100 пФ)  ──►  ADC1_CH6  ──►  SMA (16 выборок)  ──►  логика LED
                 аппаратный ФНЧ                    программный фильтр
```

## Параметры

Задаются макросами в [main/main.c](main/main.c):

| Макрос | Значение | Назначение |
|---|---|---|
| `ADC_CHANNEL` | `ADC_CHANNEL_6` | канал ADC1 на GPIO7 |
| `ADC_RESOLUTION` | `ADC_BITWIDTH_12` | разрядность 12 бит → RAW = 0…4095 |
| аттенюация | `ADC_ATTEN_DB_12` | диапазон ~0…3.1 В |
| `ADC_RAW_MIN_VALUE` | `2700` | нижняя граница рабочего диапазона |
| `ADC_RAW_MAX_VALUE` | `3700` | верхняя граница рабочего диапазона |
| `ADC_HYSTERESIS` | `100` | ширина петли гистерезиса в отсчётах АЦП |
| `LEDC_RESOLUTION` | `LEDC_TIMER_12_BIT` | duty 0…4095 |
| `LEDC_FREQ` | `5000` | частота ШИМ, Гц |
| `LEDC_MIN_DUTY` | `500` | минимальная скважность в рабочем диапазоне |
| период опроса | `100 мс` | `vTaskDelay(pdMS_TO_TICKS(100))` |

## Программная фильтрация: SMA

`sma_filter()` — простое скользящее среднее по **16 подряд идущим измерениям**:

```c
for (int i = 0; i < len; i++) {
    ESP_ERROR_CHECK(adc_oneshot_read(adc_unit_handle, ADC_CHANNEL, &raw));
    average += raw;
}
return average / len;
```

Почему это помогает:

- шум АЦП близок к случайному, поэтому усреднение по `N` выборкам уменьшает
  среднеквадратичное отклонение примерно в `√N` раз (для 16 выборок — в 4 раза);
- освещённость меняется медленно (сотни миллисекунд и больше), а шум — быстро,
  так что усреднение почти не «съедает» полезный сигнал;
- 16 — степень двойки, деление превращается в сдвиг, и накопитель `int` не переполняется
  (16 × 4095 = 65 520).

Все 16 чтений выполняются подряд, без задержек между ними, поэтому один вызов
фильтра — это фактически «мгновенный» замер с подавленным шумом. Дальше кадр
повторяется каждые 100 мс.

## Логика управления светодиодом

`map_duty()` линейно масштабирует отфильтрованный RAW в скважность **с инверсией** —
чем меньше RAW, тем больше duty:

```
duty = maxPWM − (raw − ADC_RAW_MIN_VALUE) · maxPWM / (ADC_RAW_MAX_VALUE − ADC_RAW_MIN_VALUE)
```

Результат ограничивается с обеих сторон: сверху — `maxPWM` (4095), снизу — `LEDC_MIN_DUTY` (500).
Кламп обязателен: вне рабочего диапазона выражение даёт значения за пределами
`0…4095`, а при беззнаковой арифметике ещё и переполняется по модулю 2³²
(именно поэтому промежуточные вычисления ведутся в `int32_t`, и только результат
приводится к `uint32_t`).

`check_led_conditions()` разбирает четыре зоны:

| Условие | RAW | Действие |
|---|---|---|
| рабочий диапазон | `2700 … 3700` | `set_duty(map_duty(raw))` — плавная регулировка яркости |
| петля гистерезиса | `2600 … 2699` | `set_duty(map_duty(raw))` — удержание, duty упирается в 4095 |
| выше верхней границы | `> 3700` | `set_duty(LEDC_MIN_DUTY)` — стабильная минимальная яркость |
| ниже нижнего порога | `< 2600` | `set_duty(0)` — светодиод выключен |

## Гистерезис

Два порога разнесены на `ADC_HYSTERESIS = 100` отсчётов:

- **порог включения** — `ADC_RAW_MIN_VALUE` = 2700;
- **порог выключения** — `ADC_RAW_MIN_VALUE − ADC_HYSTERESIS` = 2600.

Между 2600 и 2700 находится «мёртвая зона»: сигнал, который дрожит вокруг 2700,
не переключает светодиод, потому что для выключения нужно уйти ещё на 100 отсчётов ниже.
Без этого разноса любое колебание в один-два отсчёта на границе давало бы видимое мерцание.

Вместе с SMA получается два независимых механизма подавления мерцания:
фильтр убирает быстрый шум внутри одного замера, гистерезис — медленное «блуждание»
сигнала вокруг порога.

## Целевая платформа

ESP32-S3 (`CONFIG_IDF_TARGET="esp32s3"`). В репозитории есть devcontainer
[.devcontainer/](.devcontainer/) с ESP-IDF и QEMU.

## Сборка и запуск

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p <PORT> flash monitor
```

В мониторе видно отфильтрованное значение АЦП и текущую скважность:

```
I (xxx) adc_filters: adc raw = 3210
I (xxx) adc_filters: pwm duty = 2005
```

## Выводы

- Аппаратный RC-фильтр и программный SMA решают разные задачи: конденсатор гасит
  высокочастотные наводки **до** оцифровки (то, что АЦП уже не сможет отличить от сигнала),
  SMA усредняет остаточный шум квантования **после**. Одно другое не заменяет.
- SMA — фильтр с конечной памятью: увеличение окна улучшает подавление шума,
  но добавляет задержку реакции. 16 выборок подряд — компромисс, при котором
  задержка определяется не окном, а периодом опроса (100 мс).
- Гистерезис нужен именно на границе состояний. Даже идеально отфильтрованный сигнал
  на пороге будет пересекать его туда-обратно, потому что сама освещённость меняется
  непрерывно — разнесённые пороги превращают это в одно чёткое переключение.
- Управление светодиодом через ШИМ (а не `gpio_set_level`) даёт плавный переход
  в рабочем диапазоне, что дополнительно маскирует остаточные колебания сигнала.
